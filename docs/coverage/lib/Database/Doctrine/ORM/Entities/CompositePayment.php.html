45/**
46 * CompositePayments collect a couple of ProjectPayments of the same
47 * ProjectParticipant. In GnuCash this would be a "split transactions". The
48 * transaction parts are ProjectPayment entities which is just a "named joint
49 * table" in order to avoid ManyToMany and add some stuff.
50 *
51 * So: there are no other per-person payments, each payment thus is tied to a
52 * person and a project. For "unprojected payments" either the club members
53 * project has to be used or the executive board project. External parties
54 * also have first to be added to a project as "associates", then they are
55 * also "Musician" entities (thow the name is misleading) and then can be used
56 * as ordinary participants for payments.
57 */

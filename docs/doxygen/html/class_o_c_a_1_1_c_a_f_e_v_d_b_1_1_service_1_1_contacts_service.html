◆ importVCard()

importVCard ( null|Entities\Musician $entity,
VCard $vCard,
bool $preferWork = true,
bool $keepExisting = true )

Import the given vCard into the musician data-base.

This is somewhat problematic: the CAFeV DB database does not support fancy fields. Other things: being a layman-orchestra, we prefer private entries for everything and just choose the first stuff available if no personal data is found.

We import the following properties

N, UID, LANG, EMAIL, TEL, REV, ADR, BDAY, CATEGORIES, PHOTO

CATEGORIES are used to code instruments and project membership.

Parameters
null | Entities\\Musician$entityIf given update the given entity from the card-data, otherwise create a new entity.
VCard$vCardSerialized vCard data.
bool$preferWorkPrefer WORK variant for all properties which have multiple types. Default \true.
bool$keepExistingRather keep the properties of a given musician entity instead of overwriting them. Instruments will be added from the categories and empty fields of the given musician entity will be filled.
Returns
null|Entities\Musician entity.

Merge a musician entity into an existing contact.

The result can be fed in to IAddressBook::createOrUpdate(). The URI component of $target is preserved. If the musician is (soft-)deleted, then the link to the address-book is removed.

VCard arguments will be flattened first by ContactsService::flattenVCard().
